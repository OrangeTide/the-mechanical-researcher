# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Purpose

This is a collection of research topics, primarily gathered through agentic AI sessions, published as a blog on GitHub Pages.

## Research Topic Structure

Each topic gets its own directory, named in lower-case kebab-case (1–5 words), e.g. `quantum-error-correction/`.

Each research topic should include these sections:
- Introduction
- Abstract
- Findings
- Conclusion

Topics may also include supplementary files such as formal reports with larger datasets.

## Static Site Generator

The blog is built with a custom shell script pipeline using **lowdown** for markdown-to-HTML conversion. The site is published to GitHub Pages by a GitHub Actions workflow on every push to `main`.

### Markdown and HTML capabilities
- **lowdown** supports GFM tables natively.
- Inline SVG and raw HTML pass through with `--html-no-escapehtml --html-no-skiphtml` flags (already configured in `build.sh`).
- External SVG files can be referenced with `<img>` tags.
- **graphviz** (`dot`, `neato`, etc.) and **mscgen** are available for generating diagrams as SVG, which can be inlined into articles.

### Build
```sh
./build.sh            # builds to _build/
./build.sh -u /tmp/out   # update in-place (skip rm -rf, useful for live preview)
./build.sh /tmp/out   # builds to custom output directory
```

### Deploy
Publishing is automated by GitHub Actions (`.github/workflows/deploy.yml`):
every push to `main` runs `./build.sh` and deploys `_build/` to GitHub Pages
via the Pages deployment API. There is no manual deploy step and no `gh-pages`
branch. To publish, commit and push to `main`.

### Project layout
- `build.sh` — main build script
- `site/templates/` — HTML templates (`index.html`, `article.html`) with `{{KEY}}` placeholders
- `site/static/css/` — stylesheets (`index.css` for the index list, `article.css` for articles)
- `_build/` — generated output (gitignored)

### Topic frontmatter
Each topic's `index.md` requires YAML frontmatter:
```yaml
---
title: Topic Title
date: YYYY-MM-DD
abstract: One-line summary shown in the index list entry
category: tag-name
---
```

## Site Design

### Permalinks
Articles have permalinks — each article is at `/<slug>/index.html`. Article pages show a permalink icon.

### Index page
A plain vertical list of research entries that you scroll the normal way. No scroll hijacking and no canvas tricks, which is what keeps it working on a phone. The whole list is rendered statically by `build.sh` (no JavaScript needed on the index). Each entry shows category, date, title (a link), abstract, and a Source ZIP link when the topic has a demo. Entries are sorted newest first. The page has a sticky header (site title, tagline, RSS and GitHub links) and a footer with the about note. Palette and typography match the article pages so the two read as one publication.

The index must work at both desktop and phone widths (single column on mobile, no horizontal overflow).

### Visual language
- Thin black border (`1px solid #2c2420`) = clickable interactive element (buttons, download links)
- Thin gray border / hairline (`1px solid #d4c9b8`) = decorative or structural border (entry rules, header and footer dividers)

### Table of contents
Articles with 3+ h2 headings automatically get a TOC button. The TOC is generated by `build.sh` (grep for `<h2 id="...">` in rendered HTML) and uses a CSS checkbox hack for show/hide — no JavaScript required for toggle. TOC collapses when a link is clicked (minimal JS).

### Source packages
Topics with a `demo/` subdirectory automatically get a ZIP archive built during `./build.sh`. The ZIP is linked from the article header ("Source ZIP" button) and from that topic's entry on the index ("Source ZIP (size)").

### Typography
- Entry/article titles: IBM Plex Sans
- Body: IBM Plex Sans Condensed
- Date/category/metadata: IBM Plex Mono

### Colors
Warm paper palette — cream background, dark ink text, muted brown metadata, hairline rules.

### Article images
Article images (SVG, PNG, etc.) fit the text column width. Clicking an image opens a lightbox modal with a close button. The lightbox uses shared `.close-btn` CSS.

## Supplementary Files

When a research topic links to a `.md` file in a subdirectory (e.g. `demo/README.md`, `demo/PROTOCOL.md`), the build should produce an `.html` version alongside it. Link to both formats from the article so readers can choose.

## Screenshots

Use `tools/term-screenshot` to generate inline SVG terminal screenshots for demonstrating command-line utilities. The SVG can be inlined directly into article markdown (lowdown passes raw HTML/SVG through). Prefer screenshots over code blocks when showing actual program output.

## Website Design

Use the `frontend-design` and `web-design-guidelines` skills when designing or modifying the website's HTML/CSS/JS (index page, article layout, card stack interaction).

The website must support a mobile-friendly layout and interface for both the index page card stack and article pages.

## Demo Setup Documentation

When a research topic includes a demo with runnable code, the demo's README.md must include a clear step-by-step setup guide that a reader can follow to run it themselves. Include prerequisites, build instructions, launch order, and what to expect.

## Conventions

- The README.md maintains a list of topics with links (currently a TODO).
- When adding a new research topic, update the Topics section in README.md with a link to it.
- Each git commit should update a single topic only.
- A research topic is generally consolidated into a single commit (using fixup/amend/history rewrite as needed) before pushing.
